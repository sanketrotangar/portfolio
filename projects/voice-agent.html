Dastak: Voice Agent for Real-Estate Lead Qualification

A Hinglish voice agent that calls new property leads within a minute, qualifies buyers, books site visits and hands brokers a scored summary.

Role
Solo build, end to end: telephony and agent runtime, conversation state machine, Hinglish speech handling, booking and CRM integrations, and the simulation-based eval suite.

Problem

Property leads go cold in minutes, but brokers call back in hours, after the buyer has already spoken to a competitor. Generic voice bots fall apart on real Indian calls: Hinglish, interruptions, “call me later”, wrong numbers.

What I built

How the system runs end to end.

  • Trigger: a new lead hits a webhook (form or Sheet). A consent and calling-window check runs first.
  • Converse: the agent calls, confirms identity, then qualifies budget, area, BHK, timeline and buyer type. It handles objections and mirrors the caller’s language mix per turn.
  • Act: it checks calendar slots live and books the site visit. If the buyer is hot, it hands off to a human.
  • Report: the broker gets a summary, a lead score with the reason, and the full transcript.

Key decisions and trade-offs

What I chose, what I rejected, and why.

Choice

Pipeline over speech-to-speech.

Why: Each stage (STT, LLM, TTS) is swappable and measurable, and I control Hinglish handling. The price is stacked latency, which I recover with streaming and a measured per-stage budget.

Rejected: Monolithic speech-to-speech models (opaque, un-measurable sub-stages)

Choice

The LLM talks, code decides.

Why: A state machine owns consent, required fields and handoff. The model cannot skip consent or “forget” to collect a budget.

Rejected: Pure prompt-driven conversational control

Choice

Hinglish strategy, tested not assumed.

Why: Auto-detect versus language hints compared on my own test set, with script normalization (Devanagari/Latin) before extraction.

Rejected: Unverified language-detection defaults

Choice

Tool latency is masked, not hidden.

Why: A short spoken filler covers calendar lookups, and the gap is measured.

Rejected: Dead silence during API execution

Choice

Consent-first outbound.

Why: Calls only to people who enquired, inside calling hours, with opt-out honored instantly.

Rejected: Aggressive cold-calling outbound loops

Choice

Tiered testing.

Why: Logic tests run as text, STT tests on recorded audio, and a small number of full audio runs. This is how I kept a rigorous eval inside free-tier limits.

Rejected: Running expensive audio pipelines for simple state-logic checks
